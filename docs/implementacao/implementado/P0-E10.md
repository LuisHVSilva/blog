# P0-E10 — snapshot público

## Revisão de conformidade — 10/09/2026

Exportação agora lê revisão e todas as projeções em uma transação REPEATABLE READ somente leitura, fecha o banco e publica JSON por rename atômico. Frontend valida schema e consome esse snapshot; gera HTML completo PT/EN, metadados, canonical/alternates, sitemap, manifesto de revisão e configuração de redirects. Rotas desconhecidas têm HTTP 404 real. Runtime público deixou de importar o catálogo demonstrativo/raw; os arquivos antigos permanecem como histórico. A integração anteriormente indicada como próximo incremento está implementada e foi exercitada via API + HTML.

Evidências consolidadas e limites: [AUDITORIA-P0](./AUDITORIA-P0.md). Esta revisão prevalece sobre o relato histórico abaixo, inclusive trechos que anunciam como futuras etapas já executadas.

## Histórico da entrega inicial

Foi implementada a exportação de snapshot no backend. `ArticleReader.exportSnapshot` lê a revisão corrente e todas as traduções publicadas de artigos ativos, incluindo corpo somente no artefato de exportação. O comando `npm run content:export -- --output <arquivo>` cria diretórios necessários, grava um arquivo temporário e usa rename atômico para publicar o JSON.

O snapshot usa `schemaVersion: 1`, `revision`, `generatedAt` e artigos públicos; não inclui rascunhos, artigos arquivados, contas ou dados operacionais. A exportação fecha a conexão antes de qualquer etapa externa de build.

O escopo segue E10/R11/R15/R16 para separar a projeção pública do banco do consumo de site. Validação executada: `npm run typecheck` e `npm run build` passaram.

O próximo incremento de E10 deve conectar o snapshot ao build do frontend, prerenderização e sitemap, removendo a fonte raw antiga somente depois de o consumidor validar o schema completo.
