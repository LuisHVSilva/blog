# P0-E08 — consultas editoriais públicas

## Integração com os comandos e snapshot — 11/09/2026

Os fluxos editoriais antes fora do recorte também foram migrados. `PublicArticlePersistence` não permanece mais como leitor da exportação: `SnapshotService` reutiliza serviços públicos e repositórios de consulta sob um contexto de leitura consistente. O método `allPublished` entrega projeções imutáveis para montar o snapshot; nenhuma rota acessa o ORM diretamente. Ver [arquitetura de use cases](../../USE_CASE_ARCHITECTURE.md).

## Use cases e serviços — 10/09/2026

O fluxo HTTP agora é `ArticlesRouter → I...UseCase → I...Service → IPublic...Repository`. Foram criados cinco use cases com interface específica e classe, três serviços por responsabilidade e repositórios separados para as projeções públicas de artigo, tag e série. A injeção é por construtor, montada por `PublishingQueriesComposition`. As funções livres `listArticles` e `getArticle` foram removidas; o controller não recebe mais `ArticleReader`.

As validações independentes de HTTP ficam nos serviços; navegação e lacunas de séries não são calculadas pelo repositório novo. As projeções são classes imutáveis baseadas em `EntityBase`. Contratos HTTP e migrations permanecem iguais. A exportação/importação/publicação editorial continua no fluxo anterior, fora deste recorte.

Detalhes, comparação com Rolay e limites: [arquitetura de use cases](../../USE_CASE_ARCHITECTURE.md). Esta seção prevalece sobre a descrição histórica de acesso direto ao leitor abaixo.

## Adaptação ORM — 10/09/2026

PublicArticlePersistence implementa a interface de leitura existente; a conversão de artigos SQL para DTOs foi extraída para PublicArticlePersistenceMapper. Models e entidades não são serializados diretamente pela API. Consultas de projeção e snapshot consistente mantêm SQL parametrizado e os contratos de visibilidade/idioma. Ver [arquitetura de persistência](../../PERSISTENCE_ARCHITECTURE.md).

## Revisão de conformidade — 10/09/2026

Consultas agora projetam autor, tags, séries, SEO e alternates reais. Filtros de tag/série e busca literal são parametrizados; paginação tem inteiros seguros e desempate estável. Listas/detalhes não fazem fallback de idioma nem expõem conteúdo retirado. Séries incluem somente membros visíveis ordenados, anterior/próximo e indicação de lacunas; taxonomias vazias não são públicas.

Evidências consolidadas e limites: [AUDITORIA-P0](./AUDITORIA-P0.md). Esta revisão prevalece sobre o relato histórico abaixo, inclusive trechos que anunciam como futuras etapas já executadas.

## Histórico da entrega inicial

Foi implementado `PostgresArticleReader` e casos de uso para detalhe e listagem de artigos. As consultas usam binds, selecionam `body_markdown` somente no detalhe, filtram tradução `published` e artigo não arquivado e não aplicam fallback de locale.

A listagem aplica página, limite, dificuldade, busca literal escapada e ordenação determinística por publicação/UUID. Retorna total e `totalPages` zero quando não há resultados. Tags e séries usam traduções publicadas e contagem de artigos visíveis; a composição expõe um reader construído sobre a única instância Sequelize.

O escopo veio de E08 e R07/R13/R14: predicado de visibilidade único, locale explícito, parâmetros limitados e sem modelos ORM nos DTOs. Não foram criadas rotas HTTP; isso pertence a E09.

Validação executada: `npm run typecheck`, `npm run build` e `npm run lint` passaram.

Em E09, montar rotas Express sobre estes casos de uso, validar a query na borda, mapear `null` para 404 e implementar cache/OpenAPI. Não adicionar SQL às rotas.
