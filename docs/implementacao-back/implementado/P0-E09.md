# P0-E09 — API pública editorial e cache HTTP

## Revisão de conformidade — 10/09/2026

Rotas reais de artigos, tags e séries validam locale, slugs, filtros e paginação, rejeitando parâmetros desconhecidos/duplicados. Aliases retornam 308 apenas enquanto o destino é público. ETag deriva da representação, aceita validadores fracos/listas e tem precedência sobre If-Modified-Since. Last-Modified do detalhe usa a edição para incluir alterações de metadados relacionados sem falsificar updatedAt editorial. Erros são no-store; OpenAPI descreve endpoints e DTOs expandidos.

Evidências consolidadas e limites: [AUDITORIA-P0](./AUDITORIA-P0.md). Esta revisão prevalece sobre o relato histórico abaixo, inclusive trechos que anunciam como futuras etapas já executadas.

## Histórico da entrega inicial

Foram criadas as rotas públicas `GET /api/v1/articles` e `GET /api/v1/articles/by-slug/:locale/:slug`. Elas adaptam a query para os casos de uso de E08, rejeitam locale, paginação, dificuldade, ordenação e campos desconhecidos inválidos e nunca expõem escrita editorial.

As respostas publicadas usam `Cache-Control: public, max-age=0, s-maxage=60, must-revalidate`, ETag calculada sobre a representação e `304` para `If-None-Match`. Detalhe inexistente, draft ou arquivado retorna o mesmo 404 público. `openapi.yaml` documenta os recursos iniciais e suas respostas.

A composition monta o router sobre o `PostgresArticleReader`; as rotas não importam Sequelize nem escrevem SQL. O escopo veio de E09/R03/R13/R14/R15, mantendo a leitura sem sessão e as mutações inexistentes nesta borda.

Validação executada: `npm run typecheck`, `npm run lint` e `npm run build` passaram.

E10 deve exportar o snapshot completo da mesma projeção pública para o frontend e sitemap, incluindo taxonomia/séries e redirects de slug.
