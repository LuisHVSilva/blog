# P0-E11 — imagens e Compose reproduzíveis

## Revisão de conformidade — 10/09/2026

compose.yaml na raiz é a entrada local canônica: PostgreSQL saudável → migrate → seed/export → API + build do site → nginx. API e banco ficam internos; somente localhost:8080 é publicado. Runtime da API é compilado e não root. Proxy tem limites, timeout, 404 e DNS Docker reavaliado para suportar recriação da API. Compose legado de desenvolvimento preserva seu volume e corrigiu a porta interna configurável. A composição local não representa deploy de produção nem troca atômica de release.

Evidências consolidadas e limites: [AUDITORIA-P0](./AUDITORIA-P0.md). Esta revisão prevalece sobre o relato histórico abaixo, inclusive trechos que anunciam como futuras etapas já executadas.

## Histórico da entrega inicial

Foi criada a imagem de produção em `backend/Dockerfile`. Ela instala dependências por lockfile, compila o backend, remove dependências de desenvolvimento e executa `dist/src/main.js` como usuário `node`, sem montar fonte ou ambiente no artefato.

`backend/docker-compose.yml` define PostgreSQL 16 persistente, job `migrate` separado e API. A API só inicia depois de o job de migrations terminar com sucesso. Segredos permanecem em `.env.production`, fora do contexto de imagem; o Compose não cria volume de código nem expõe o banco.

Foi incluído `npm run production:compose` para iniciar essa topologia com `--env-file .env.production`. O Compose de desenvolvimento e seu live reload permanecem separados em `docker-compose-develop.yml`.

O escopo segue E11/R01/R04/R17: artefato compilado, migration serializada e ambiente reproduzível. Validação executada: `npm run typecheck` e parse de `package.json` passaram.

E12 deve adicionar o smoke de release, backup/restore e os runbooks com host, domínio, responsáveis e RPO/RTO definidos pelo mantenedor antes de publicar.
